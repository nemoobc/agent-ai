# Documentation

## When to use
Write README, API docs, ADRs, runbooks, or migration guides. Only create docs when explicitly requested.

## Key rules
- Write for the reader, not the author; be clear over clever
- Include runnable examples; test them before publishing
- Use consistent structure: title, purpose, usage, examples, references
- Keep docs near the code they describe
- Version docs alongside code; date significant changes

## Anti-patterns
- Don't create unsolicited README files
- Don't duplicate information available in code comments
- Don't write docs that will rot — prefer executable examples
