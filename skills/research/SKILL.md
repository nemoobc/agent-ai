# RESEARCH

Pengetahuan kedaluwarsa = bug yang menunggu. Riset dulu, klaim belakangan.

## KAPAN
- Versi library/API yang belum pernah dipakai di project ini
- Keputusan pemilihan tool/service
- Harga & limit (masuk skill cost sebagai sumber angka)
- Best practice yang diperdebatkan (jangan hafalkan, cek terkini)

## CARA
1. **SARING** — bisa dijawab dari repo/memori? → jangan riset. Mulai dari README, CHANGELOG, config.
2. **CARI** — web_search/read_url. Prioritas: docs resmi > release notes > issue tracker > blog.
3. **CATAT SUMBER** — tiap klaim wajib pasangan URL + tanggal akses. Tanpa sumber = opini, bukan temuan.
4. **COCOKKAN** — versi & instruksi cocokkan dengan kondisi project sekarang (versi runtime, framework).
5. **SIMPAN** — temuan penting → plan/memori dengan sumbernya. Review sesi berikutnya pakai recall.

## FORMAT TEMUAN
```
RISET : <topik>
S1    : <klaim> — <URL> (<tanggal>)
S2    : <klaim> — <URL> (<tanggal>)
SIMPUL: <keputusan 1 kalimat + alasannya>
```

## GERBANG
- Klaim tanpa sumber = DILARANG masuk plan/laporan.
- Dua sumber bertentangan → sebut keduanya + pilih yang resmi, catat risiko.
- Riset berbiaya (API call) → lewat skill cost dulu (HUKUM 5).
