# Software Engineering

## When to use
Production implementation, refactoring, architecture decisions, and code maintenance. Prioritize simplicity and maintainability.

## Key rules
- Make the change easy first, then make the easy change
- Prefer composition over inheritance; favor small focused modules
- Write code that reveals intent; name things clearly
- Refactor in small steps; keep tests passing at each step
- Remove dead code; don't leave "just in case" logic

## Principles
- YAGNI: don't build what you don't need yet
- KISS: simplest solution that works
- DRY: but only when the duplication is real, not coincidental
- SOLID: as guidelines, not rigid rules
